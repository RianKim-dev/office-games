# 제품 문서

이 문서는 office-games가 무엇이고 무엇이 아닌지를 정한다. 게임별 요건은 `docs/games/`에 있다.
이 문서와 충돌하는 구현은 허용하지 않는다. 문서를 고쳐야 한다고 판단되면 구현하지 말고 제안한다.

## 1. 제품 정의

서로 다른 회사에 다니는 친구들이 업무 시간 중에 각자의 회사 PC로 접속해서,
업무 도구처럼 보이는 화면에서 짧게 즐기는 미니게임 서비스다.
한 번에 모이는 인원은 5명 안팎이다.

## 2. 원칙

1. **시작하기까지 드는 수고가 적어야 한다.**
   이전 버전의 빙고는 판을 채우는 준비가 부담스럽고 진행 방식이 어려워서 쓰이지 않았다.
2. **다른 창에서 업무를 하다가 차례가 되면 돌아오는 사용 방식을 정상으로 취급한다.**
   창이 보이는지 여부나 접속 상태를 근거로 참가자가 자리에 있는지를 판단하지 않는다.
3. **한 사람이 자리를 비워도 나머지 사람들의 게임은 멈추지 않는다.**
4. **게임 규칙은 서버에서 실행한다.**
   이전 버전은 각 브라우저가 규칙을 실행하고 DB에 직접 기록해서 경쟁 상태 결함이 반복되었다.
5. **요청되지 않은 기능은 만들지 않는다.** 필요해 보이면 만들지 말고 제안한다.

## 3. 공통 사용자 흐름

### 첫 화면

서비스 주소를 방 링크 없이 열었을 때 나오는 화면이다. 다음 두 가지가 있다.

- 새 방 만들기
- 이 브라우저로 최근에 들어갔던 방의 목록. 이미 없어진 방은 보여 주지 않는다.
  이 기록은 서버가 아니라 각자의 브라우저에 저장한다.

### 입장

- 초대 링크가 유일한 입장 경로다. 링크를 열면 첫 화면을 거치지 않고 해당 방으로 들어간다.
- 방 안에서는 누구나 초대 링크를 복사할 수 있다.
- 들어올 때 이름을 입력한다. 입력한 이름은 브라우저에 기억해 두고,
  다음에 방에 들어올 때 입력란에 미리 채워 둔다. 수정할 수 있다.
- 같은 이름을 쓰는 것을 막지 않는다. 한 방에서 이름이 겹치면 화면에서 구분되도록 표시한다.
- 방의 정원은 8명이다. 게임마다 필요한 인원은 게임별 요건에서 따로 정한다.

### 대기 화면

- 방에 있는 누구나 게임을 고르고 시작할 수 있다. 방장은 없다.
- 두 사람이 동시에 시작을 요청하면 서버에 먼저 도착한 요청만 받아들인다.
- 참가자는 참가 상태이거나 관전 상태다. 방에 들어온 사람은 기본적으로 참가 상태다.
- 시작하는 시점에 참가 상태인 사람들로 판이 구성된다.

### 판 진행 중

- 모든 차례에는 제한 시간이 있다.
- 자기 차례에 제한 시간 안에 행동하지 않은 것을 자리 비움으로 판단한다.
  잠깐 자리를 비웠다가 제한 시간 안에 돌아온 사람에게는 불이익이 없다.
- 자리 비움으로 판단된 사람은 그 판에서 제외되고 관전 상태로 바뀐다.
  그 사람 없이 진행할 수 있는 게임이라면 남은 사람들끼리 계속 진행한다.
- 제한 시간의 길이, 몇 번 넘겼을 때 제외하는지, 차례가 없는 게임에서의 처리는 게임별 요건에서 정한다.
- 누구나 진행 중인 판을 중단하고 모두를 대기 화면으로 돌려보낼 수 있다.

### 관전

- 제외된 사람과 판 도중에 방에 들어온 사람은 그 판을 관전한다.
- 관전자에게는 모든 참가자에게 공개된 정보만 보인다. 다른 사람의 손패나 판처럼 숨겨진 정보는 보이지 않는다.
- 제외된 사람은 본인이 직접 참가 상태로 되돌려야 다음 판에 포함된다. 자동으로 다시 포함되지 않는다.
- 판 도중에 들어온 사람은 참가 상태이므로 다음 판부터 포함된다.

### 판 종료

- 모두 대기 화면으로 돌아온다.
- 같은 게임을 다시 시작하거나 다른 게임을 고른다. 방과 초대 링크는 그대로 유지된다.

### 방 소멸

- 방에 접속한 사람이 아무도 없는 상태가 짧은 유예 시간 동안 이어지면 방이 없어진다.
  유예 시간은 새로 고침이나 순간적인 네트워크 끊김을 흡수하는 정도의 길이다.
- 진행 중이던 판이 있었다면 함께 사라진다.
- 없어진 방의 링크를 열면 방이 없어졌다는 안내와 함께 새 방을 만드는 길을 보여 준다.

## 4. 위장 규칙

위장이 견뎌야 하는 시선은 **지나가던 사람이 모니터를 한두 초 흘끗 보는 정도**다.

1. 소리는 어떤 경우에도 사용하지 않는다.
2. 어느 순간의 화면이든 한두 초 동안 보았을 때 위장 대상인 업무 도구로 보여야 한다.
   - 판단 대상: 화면 배치, 색감, 움직임의 정도, 브라우저 탭의 제목과 아이콘
   - 판단 대상이 아닌 것: 화면 안의 글자 내용, 주소창의 주소
   - 차례 표시, 승패 표시, 오류 안내도 이 조건을 지킨다.
3. 2번을 지키는 범위 안에서는 위장의 정교함보다 게임의 편의성을 우선한다.
4. 알려야 하는 일이 있으면 그 업무 도구가 원래 사용하는 표현 방식으로 알린다.
   메신저는 읽지 않은 메시지를 표시하고, 칸반 보드는 카드의 상태를 바꾸며, 스프레드시트는 셀을 강조한다.
5. **예외**: "당신 차례입니다" 안내와 승리 연출은 2번의 적용을 받지 않는다.
   - 이 두 가지는 공통 화면에서 한 번만 만든다. 각 게임은 "차례가 되었다", "누가 이겼다"는 사실만 알리고
     직접 연출을 만들지 않는다.
   - 나중에 빼거나 수위를 낮출 수 있는 잠정적인 결정이다.
   - 이 두 가지 외의 연출을 추가하려면 제안해서 승인을 받는다.

### 화면별 위장 대상

| 화면 | 위장 대상 |
|---|---|
| 첫 화면, 대기 화면 | 여러 업무 도구를 모아 둔 사내 업무 포털. 게임을 고르는 행동이 도구를 여는 행동처럼 보인다. |
| 빙고 | 칸반 보드 |
| 끝말잇기 | 메신저 |
| 오목 | 스프레드시트 |
| 원카드 | 스프린트 백로그 |
| 타자경주 | 문서 편집기 |
| 캐치마인드 | 화이트보드 |

## 5. 범위

### 만드는 것

- 방, 초대 링크, 대기 화면, 관전, 판 중단
- 1차 게임: 빙고, 끝말잇기, 오목, 원카드, 타자경주, 캐치마인드

### 만들지 않는 것

- 계정과 로그인
- 전적과 순위
- 자유 대화 채팅. 캐치마인드의 정답 입력은 예외다.
- 관리자 화면
- 다국어 지원
- 방 검색과 전체 방 목록
- 방장 권한, 방 비밀번호
- 휴대폰 화면에 맞춘 배치

### 지원 환경

PC의 브라우저만 지원한다. 휴대폰에서는 화면이 좁고 불편하게 보일 수 있다.
나중에 모바일을 지원하게 될 때 다시 만들 부분을 화면 배치로 한정하기 위해 다음 두 가지를 지킨다.

- 마우스와 터치를 함께 처리하는 입력 방식을 사용한다.
- 게임을 진행하는 데 반드시 필요한 조작을, 마우스를 올려놓아야만 나타나는 요소에 두지 않는다.
